# ADS-002 — Debug test IDs and release ad configuration

Status: IN PROGRESS  
Tracking: issue #116 / PR #117

## Audit findings

- Debug Android configuration uses Google's documented public AdMob test application/ad-unit IDs.
- Android release application ID is externalized through `ADMOB_ANDROID_APP_ID`; Gradle rejects missing and Google-test application IDs and does not fall back to debug signing.
- `VERIFY_RELEASE_INPUTS.ps1` validates production application/ad-unit ID formats, rejects Google test IDs, validates signing inputs, and reports only redacted state.
- `AdService` reads banner/rewarded/interstitial IDs only from `AppBuildConfig.current`.
- The Android RC builder injects Android runtime ad-unit IDs only. The prior typed runtime validation checked Android and iOS IDs together, so unused iOS Google-test defaults could reject an otherwise valid Android ads-enabled release.
- Typed validation also previously accepted arbitrary non-empty non-test strings when a build bypassed the RC PowerShell preflight.

## Implementation checkpoint

- Runtime AdMob validation is now scoped to the active platform.
- Active-platform IDs must match `ca-app-pub-<16 digits>/<10 digits>`.
- Release still rejects Google public test ad-unit IDs.
- Android release regression coverage keeps untouched iOS test defaults while validating production Android IDs, plus malformed/test/disabled cases.
- Dart 3.12.2 canonical formatting was applied by the temporary one-shot formatter; the helper workflow removed itself from the branch.
