# REW-007 — Reward transaction ledger and reconciliation

Status: IN PROGRESS  
Tracking: issue #119 / RC-001 #79

## Audit findings

- `ProgressStore.completeLevel()` applies base coins, XP, mission progress, first-clear milestone/world bonuses, booster grants, stars, unlocks, and statistics in memory before persisting them across multiple preference keys.
- First-clear checks prevent a normal repeated milestone/world bonus, but an interruption during persistence can leave a partial reward transaction.
- `claimDailyReward()` and `claimDailyMission()` have duplicate guards, but their claim marker and wallet/stat writes are also separate operations and can be interrupted between keys.
- Shop purchases already use a persisted absolute-state journal with recovery; REW-007 should reuse that proven pattern instead of introducing a second transaction model.

## Implementation direction

- Add a versioned pending reward transaction journal containing a stable reason/idempotency key and validated absolute final values.
- Recover the journal before normal state load so interrupted writes converge to the intended final state.
- Persist a bounded completed-idempotency set/ledger so replayed grant requests become no-ops.
- Integrate release-critical level completion, daily reward, and daily mission reward paths without changing reward amounts.
- Preserve legacy saves by defaulting absent ledger keys to empty state.

## Verification required

- Focused idempotency/recovery/corrupt-journal/legacy-save regressions.
- Existing milestone/world/daily/progress/shop tests remain green.

- Catalog/status reconciliation after merge.
