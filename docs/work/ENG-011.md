## Goal

Make setup, daily development, Android execution, repair, dashboard access, CI-parity verification, and release packaging reproducible from a clean checkout through one canonical workflow that matches the repository's current architecture.

## Audit finding

The prior root README contained obsolete bootstrap/release guidance from an earlier project state. It directed developers to regenerate Flutter scaffolding over the project, edit advertising IDs in tracked files, and add consent support manually. Current main already tracks Android/iOS project files, externalizes release AdMob/signing inputs, validates them through release preflight, and implements Google UMP through ADS-007.

## Verified implementation

- `docs/DEVELOPER_WORKFLOWS.md` is the canonical clean-checkout, first-run, day-to-day run, Android target, repair, dashboard, CI-parity, release, privacy, and troubleshooting guide.
- `README.md` now delegates to the current supported tooling and no longer contains project-regeneration, tracked AdMob-ID replacement, manual UMP, or unguarded release-build instructions.
- The supported Windows surface is explicitly anchored to `START_CARGAME_TOOL.bat`, `START_CARGAME_TOOL.ps1`, `SETUP_TOOL.ps1`, `FIRST_TIME_SETUP_AND_RUN.ps1`, `RUN_ON_EMULATOR.ps1`, `REPAIR_ANDROID_BUILD.ps1`, `REPAIR_KOTLIN_CACHE_AND_BUILD.ps1`, `OPEN_DEVELOPMENT_DASHBOARD.ps1`, `VERIFY_RELEASE_INPUTS.ps1`, and `BUILD_RC.ps1`.
- Production AdMob/signing inputs remain external to source control and release packaging remains behind the existing preflight/RC wrappers.
- Existing ADS-007 UMP integration is documented as authoritative so developer docs cannot instruct a duplicate manual consent integration.
- `tool/verify_developer_workflows.py` checks 16 required entry-point/doc files, mandatory current workflow tokens, external-release-input guidance, source-controlled platform-project guidance, and forbidden stale patterns.
- `tool/test_developer_workflows.py` provides 10 regressions covering valid repository/text contracts, missing scripts, project regeneration, obsolete bootstrap guidance, tracked AdMob replacement, manual UMP duplication, hard-coded emulator serials, direct release bypass, and missing release wrapper guidance.
- Flutter CI now runs `Verify developer workflow documentation` and `Test developer workflow documentation` as blocking gates before package restore.
