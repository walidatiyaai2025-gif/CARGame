# AST-003 — Missing-asset fallback

Status: IN PROGRESS
Started: 2026-08-07
Owner: active engineering team

## Goal

Missing or corrupt 3D assets must never crash the app or leave an invisible gameplay/UI object.

## Implementation contract

- Add one shared asset rendering primitive backed by the AST-002 descriptor/registry.
- Use Flutter image error handling for missing and corrupt runtime files.
- Support icon, text, registered-asset, and generic fallback paths.
- Detect fallback-asset cycles and terminate in a visible generic fallback.
- Preserve meaningful/decorative semantics contracts.
- Keep fallback dimensions bounded and deterministic.

## Acceptance

- Missing bundle key renders a visible fallback without uncaught Flutter errors.
- Corrupt image bytes render a visible fallback without uncaught Flutter errors.
- Registered fallback assets can chain safely and cycles cannot recurse forever.
- Decorative assets are excluded from semantics; meaningful assets retain an image semantic label.
- Focused widget tests pass plus Flutter format/analyze/full tests/debug APK before closure.
