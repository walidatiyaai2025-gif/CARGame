## Architecture decision

Do not renumber or expand the gameplay archetype IDs as a visual-content shortcut. Add a separate visual identity layer:

1. gameplay archetype ID remains the matching/save/reward authority;
2. each archetype owns multiple stable `cargo.*` visual identities;
3. a pure deterministic resolver chooses a visual by level number + archetype ID;
4. cargo tile, warehouse target and travel flight use the same resolved visual;
5. missing/unadmitted runtime images render the existing Flutter fallback;
6. AST-011 provenance/licensing remains mandatory before a real WebP can be admitted.
