# AST-011 — Asset licensing and provenance

Status: VERIFIED
Started: 2026-08-07
Verified: 2026-08-09
Owner: active engineering team
Tracking: issue #130 / RC-001 #79

## Goal

No external, commissioned, licensed, or generated binary asset may enter the runtime bundle without a complete commercial-use provenance record that matches the AST-002 registry entry.

## Required provenance fields

- stable asset ID and runtime path
- source type: original, commissioned, licensed, or generated
- creator/vendor/tool and creation date
- commercial-use license/contract/ownership reference
- generation prompt and reference-file identifiers when generated
- source/master SHA-256 and exported-file SHA-256
- render profile, revision, dimensions, encoder, and quality
- reviewer and approval date
- attribution text and prohibited-use conditions when applicable

## Acceptance

- Versioned machine-readable provenance catalog exists.
- Duplicate IDs, malformed hashes/dates/revisions, missing commercial-use references, and incomplete generated records are rejected.
- Provenance records validate against AST-002 descriptor path/profile/dimensions.
- A completeness/admission gate rejects runtime WebP binaries without matching provenance and rejects orphan provenance records without matching runtime binaries.
- Descriptor-only manifest entries remain valid before binary art is authored.
- Empty runtime binary set + empty provenance catalog remains valid while no binary art is admitted.
- Focused tests plus format/analyze/full tests/debug APK pass before closure.

## Historical implementation evidence

- Added typed provenance records and a versioned provenance catalog with strict source-type, commercial-use, SHA-256, date, revision, render-profile, dimensions, encoder/quality, reviewer/approval, attribution, prohibited-use, and generated-prompt validation.
- Added cross-catalog validation against the AST-002 registry, including missing-provenance and orphan-provenance rejection plus path/profile/dimension/revision matching.
- Added `GameAssetAdmission` so runtime WebP admission is fail-closed while planned descriptor/fallback entries can exist before binary art is authored.
- Added focused provenance/admission tests and `tool/validate_asset_pipeline.dart`, wired into Flutter CI as `Validate 3D asset registry and provenance`.
- Historical Flutter CI #121 / run `31185774162` on implementation head `1d6597de0c298b40dd1f1c305f7fdeca26a2d37a` passed format, whitespace validation, Analyze, focused regressions, the full Flutter test suite, Debug APK build, and artifact upload.
