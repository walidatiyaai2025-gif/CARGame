# UI3D-006 — Responsive screen shell and safe areas

Status: VERIFIED
Started: 2026-08-07
Verified: 2026-08-09
Owner: active engineering team

## Goal

Keep bounded game screens fully visible across supported phone/tablet viewports, accessibility scaling, safe-area cutouts, and temporary viewport reductions without introducing unnecessary scrolling.

## Implementation evidence

- Shared `GameFitView` provides one bounded, scale-down screen primitive.
- Home, Mission Briefing, and Settings use the shared fit shell; long-form screens such as Progress Hub, Shop, and World Map remain scrollable by design.
- `GameFitView` applies outer padding before measuring its `LayoutBuilder`, so the fitted `SizedBox` uses the post-padding viewport instead of accidentally sizing to pre-padding constraints.
- The shell preserves caller directionality and uses `BoxFit.scaleDown`, so content renders at natural size when possible and only scales down when required.
- Settings regression coverage verifies that bounded content does not fall back to `ListView` or `SingleChildScrollView`.
- Gameplay and result-flow regressions verify compact reachability, guarded back behavior, RTL, and cutout layouts without introducing off-screen action races.

## Verification matrix

- 360×640 compact phone.
- 412×915 reference phone.
- 800×1280 and 1024×1366 tablet viewports.
- 1.6×–2× text scaling across compact and tablet cases.
- Simulated display cutout/safe-area padding.
- Simulated keyboard/view-inset reduction.
- Arabic/RTL and explicit RTL direction contracts.
- Intentionally scrollable Shop, Progress Hub, and World Map reachability.
- Compact loss-result sheet, Retry reachability, and guarded system-back behavior.
