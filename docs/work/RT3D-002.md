## Goal

Move CARGame from the RT3D-001 projected visual laboratory to the first governed native Android 3D visual slice without a WebView/model-viewer shortcut, without raising the Android baseline, and without admitting an unprovenanced model binary. The first 30 tasks established fail-closed admission contracts; tasks 31–60 select and integrate a real native renderer, commit a deterministic GLB scene, preserve the existing drag/drop domain truth, and make the native slice reachable in the Android application.

## Native slice assets and integration

- Renderer: Google Filament `1.74.0` on Android.
- Runtime asset: `assets/3d/runtime/models/cargame_native_slice_v1.glb`.
- Runtime asset SHA-256: `bfd04d6d5f6d4e5c13dd7fc6f851e173d085b64be2fd90eed2664ce9f58feacc`.
- Runtime asset size: 4276 bytes.
- Runtime scene: 12 named nodes, including a vehicle, four cargo nodes, warehouse/environment, two delivery targets, ground, and road.
- PBR material set: eight glTF metallic-roughness materials.
- Android bridge: Flutter `AndroidView` → `NativeFilamentSceneFactory` → `NativeFilamentSceneView`.
- Interaction bridge: `NativeFilamentRealtime3dScene` preserves `Realtime3dScenePort` and forwards renderer transforms through a per-view `MethodChannel`.

## Truth boundary

Google Filament 1.74.0 is admitted as the Android native GPU renderer for this checkpoint.

`cargame_native_slice_v1.glb` is admitted as a project-generated runtime GLB with pinned provenance and SHA-256.

The Android 3D Visual Lab now hosts the native Filament scene through a Flutter PlatformView.

The projected renderer remains only as an explicit non-Android fallback; it is not the Android production renderer.
