# REL-001 — Dynamic Android device targeting

Status: IN PROGRESS
Started: 2026-08-07
Owner: Codex engineering workstream

## Goal

Prevent Android build/run/diagnostic tooling from depending on a developer-specific emulator serial, physical-device serial, or AVD name.

## Scope

- Keep existing runtime discovery behavior in PowerShell/batch tooling intact.
- Add a repository validator that scans Android helper scripts for fixed emulator serials, literal `adb -s` targets, literal `-avd` values, and non-empty hard-coded `AvdName` defaults.
- Run the validator in Flutter CI so future regressions fail before merge.
- Do not rename devices, change emulator profiles, or require one workstation-specific AVD.

## Acceptance

- Existing `.ps1`, `.bat`, and `.cmd` tooling passes the dynamic-target validator.
- A future committed `emulator-5554`, literal adb target, or fixed AVD default/argument fails CI with file/line diagnostics.
- Flutter CI runs the validator on every push/PR before the normal Flutter checks.
- Existing dynamic `emulator -list-avds`, `adb devices`, and parameter-driven selection remain supported.
- Format, Analyze, full tests, and Debug APK must pass before this feature is marked VERIFIED.
