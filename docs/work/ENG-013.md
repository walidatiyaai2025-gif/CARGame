# ENG-013 — Crash reporting and non-fatal diagnostics

## Goal

Establish release-safe crash/non-fatal diagnostics boundaries while keeping CARGame offline-first and preserving the current no-remote-diagnostics privacy posture.

## Issue

- GitHub Issue #177
- PR #178
- Branch: `agent/eng-013-crash-reporting`

## Current checkpoint

`VERIFIED` — vendor-neutral crash reporting, effective local diagnostics build gating, default-off remote diagnostics privacy/config gating, bounded redacted payloads, release correlation, machine drift protection, and full repository verification are complete.

## Architecture

- Application layer owns `CrashReport`, `CrashReportContext`, `CrashReportingPort`, and `CrashReportingPrivacyPort`.
- `AppErrorBoundary` classifies Flutter, platform, isolate, and explicit non-fatal failures.
- `AppLogger` remains the local diagnostics implementation and is now effectively controlled by `ENABLE_DIAGNOSTICS`.
- `PrivacyGatedCrashReporting` sanitizes/bounds payloads immediately before any future outward emitter.
- `ENABLE_REMOTE_DIAGNOSTICS` is a separate build-time eligibility gate and defaults to false.

## Privacy rules

- No Firebase Crashlytics, Sentry, Bugsnag, Datadog, New Relic, Instabug, or other crash SDK is introduced.
- No remote diagnostics backend, queue, retry worker, upload, persistence path, or new network processor is introduced.
- Google UMP advertising consent is not reused as diagnostics consent.
- Production runtime remote diagnostics privacy remains deny-all and no emitter is installed.
- Crash payloads are secret/path-redacted and bounded before a future emitter could receive them.
- Correlation metadata is limited to app version, build number, environment, source, severity, and UTC timestamp; no account/device identifier is added.

## Acceptance

- Local logger retention/output obeys `ENABLE_DIAGNOSTICS`.
- Crash reports have schema version 1 and stable structured metadata.
- Remote reporting remains disabled without config + explicit runtime privacy + emitter.
- Flutter/platform/isolate failures and explicit non-fatals flow through the reporting boundary without affecting local error handling.
- Emitter failures never affect startup/gameplay.
- Machine privacy inventory keeps remote diagnostics disabled and declares no new network processor.
- CI blocks crash SDK/processor drift, missing redaction/bounds, default-on reporting, and build-version correlation drift.
- Formatting, Analyze, focused tests, full Flutter suite, Debug APK, privacy/security/dependency/catalog, and artifact-security gates pass before VERIFIED.
